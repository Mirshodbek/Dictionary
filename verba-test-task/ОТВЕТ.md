# Часть 1. Задача 1. Логика голосового робота-напоминания

## Входные данные

```json
{
  "appointmentId": "A-10245",
  "patientName": "Анна",
  "doctor": "Иванов Сергей Петрович",
  "specialty": "терапевт",
  "date": "2026-10-12",
  "time": "15:30",
  "clinic": "Клиника на Ленина, 15"
}
```

## Переменные сценария

| Переменная | Назначение |
|---|---|
| `fail_count` | сколько раз подряд робот не понял пациента (сбрасывается после любой распознанной реплики) |
| `question_count` | сколько вопросов уже задал пациент (защита от бесконечного разговора, лимит 3) |
| `result` | итог звонка для записи в систему клиники: `confirmed`, `cancelled`, `reschedule_request`, `wrong_number`, `no_result`, `operator` |

## Схема состояний

```mermaid
stateDiagram-v2
    [*] --> Greeting
    Greeting --> CheckPerson: «Здравствуйте, это Анна?»
    CheckPerson --> Reminder: да / это я
    CheckPerson --> WrongNumber: нет / ошиблись номером
    CheckPerson --> CheckPerson: не понял (переспросить 1 раз)
    CheckPerson --> Goodbye: не понял 2 раза: перезвоним позже

    Reminder --> WaitIntent: сообщить запись и спросить «Вы придёте?»
    WaitIntent --> Confirm: подтверждение
    WaitIntent --> Cancel: отмена
    WaitIntent --> Reschedule: перенос
    WaitIntent --> Answer: вопрос о записи
    WaitIntent --> Answer: подтверждение + вопрос (сначала фиксируем подтверждение)
    WaitIntent --> NotUnderstood: не распознано
    WaitIntent --> WrongNumber: ошиблись номером

    Answer --> WaitIntent: ответить и вернуться к вопросу «Вы придёте?»
    Answer --> Goodbye: подтверждение уже получено
    NotUnderstood --> WaitIntent: 1-й раз: переспросить проще
    NotUnderstood --> Operator: 2-й раз подряд

    Confirm --> Goodbye
    Cancel --> Goodbye
    Reschedule --> Operator
    WrongNumber --> Goodbye
    Operator --> [*]
    Goodbye --> [*]
```

## Реплики и переходы

### 0. Начало звонка
1. Робот: «Здравствуйте! Это клиника на Ленина, 15. Я говорю с Анной?»
2. Если «да» → **Напоминание**.
3. Если «нет», «вы ошиблись номером», «здесь такой нет» → **Ошибка номера** (п. 7).
4. Если ответ не распознан → один раз переспросить. Если снова непонятно → данные записи **не озвучиваются** (личность не подтверждена): «Извините, перезвоним вам позже», `result = no_result`, звонок ставится на повторный набор.

**Напоминание.** «Анна, напоминаем: вы записаны к врачу Иванову Сергею Петровичу, терапевту, на 12 октября в 15:30, по адресу: Ленина, 15. Подскажите, вы придёте?»

Дальше робот классифицирует ответ по намерениям (intent).

### 1. Пациент подтверждает запись
Примеры: «да», «приду», «конечно», «буду».
- `result = confirmed`, запись в системе помечается как подтверждённая.
- Робот: «Отлично, ждём вас 12 октября в 15:30. Пожалуйста, приходите за 10 минут. До свидания!» → конец.

### 2. Пациент хочет отменить запись
Примеры: «нет, не приду», «отмените», «не смогу».
- Уточнение (защита от ошибки распознавания): «Правильно понимаю, отменить запись на 12 октября в 15:30?»
  - «да» → `result = cancelled`, запись отменяется в системе. Робот: «Запись отменена. Если захотите записаться снова, позвоните в клинику. До свидания!»
  - «нет» → вернуться к вопросу «Вы придёте?».
- Если в реплике звучит «не смогу в это время» — это скорее перенос, робот предлагает: «Хотите перенести запись на другое время?»

### 3. Пациент хочет перенести запись
Примеры: «можно перенести?», «давайте на другой день».
- `result = reschedule_request`.
- Если в системе есть API свободных слотов: робот предлагает 2–3 ближайших времени, пациент выбирает, робот подтверждает новое время и отменяет старое.
- Если API нет: «Сейчас переведу вас на администратора, он подберёт удобное время» → перевод на оператора (или создание заявки на обратный звонок, если операторы заняты).

### 4. Пациент задаёт вопрос о записи
Робот отвечает только данными из записи:
| Вопрос | Ответ |
|---|---|
| «Во сколько у меня запись?» | «Ваша запись 12 октября в 15:30.» |
| «Напомните адрес клиники» | «Клиника находится по адресу: Ленина, 15.» |
| «К какому врачу?» | «К терапевту Иванову Сергею Петровичу.» |
| Вопрос вне данных (цены, анализы, подготовка) | «К сожалению, я не могу ответить на этот вопрос. Могу перевести вас на администратора.» |

После ответа робот **возвращается к основному сценарию**: «Подскажите, вы придёте?» (если подтверждения ещё не было).
`question_count += 1`; после 3 вопросов подряд без ответа на главный вопрос предлагается перевод на оператора.

### 5. Робот не понял ответ пациента
- `fail_count = 1`.
- Робот переспрашивает проще и с подсказкой вариантов: «Извините, не расслышал. Скажите, пожалуйста: вы придёте на приём, хотите отменить или перенести запись?»

### 6. Робот два раза подряд не понял пациента
- `fail_count = 2` (счётчик сбрасывается после любой понятой реплики, поэтому «подряд»).
- Робот: «Извините, мне не удаётся вас понять. Сейчас переведу вас на администратора.»
- Перевод на оператора; если оператор недоступен: `result = no_result`, звонок ставится в очередь на повторный набор или на обратный звонок администратора.
- Тишина (пациент молчит) обрабатывается так же, как непонятый ответ.

### 7. «Вы ошиблись номером»
- Робот **не называет** врача, время и адрес постороннему человеку (это персональные медицинские данные). Поэтому проверка личности идёт до напоминания.
- Робот: «Извините за беспокойство. Хорошего дня!» → конец.
- `result = wrong_number`, номер помечается в системе для проверки администратором, повторный звонок на него не делается.

### 8. «Да, приду. А какой адрес?» — несколько намерений в одной реплике
Реплика разбирается не на одно намерение, а на список: `[confirm, question:address]`.
Порядок обработки:
1. Сначала фиксируется главное действие: `result = confirmed` (чтобы подтверждение не потерялось, даже если связь оборвётся).
2. Затем робот отвечает на вопрос.
3. Повторно спрашивать «Вы придёте?» **не нужно**, подтверждение уже получено.

Робот: «Отлично, запись подтверждена. Клиника находится по адресу: Ленина, 15. Ждём вас 12 октября в 15:30. Остались ли у вас вопросы?» → если вопросов нет, прощание.

Если в одной реплике противоречие («Да, приду… хотя нет, перенесите») — берётся последнее высказанное намерение, и робот его уточняет.

## Псевдокод основного цикла

```
say(greeting)
if not is_patient(listen()): handle_wrong_number(); end

say(reminder_text(appointment))
confirmed = false
fail_count = 0

loop:
    intents = classify(listen())          # список намерений из реплики

    if intents is empty:
        fail_count += 1
        if fail_count >= 2: transfer_to_operator(); end
        say(reprompt_with_options); continue
    fail_count = 0

    if wrong_number in intents: handle_wrong_number(); end
    if confirm in intents:      confirmed = true; save_result("confirmed")
    if cancel in intents:       if ask_cancel_confirmation(): save_result("cancelled"); say(bye); end
    if reschedule in intents:   save_result("reschedule_request"); offer_slots_or_transfer(); end

    for q in questions(intents): say(answer_from_appointment(q))

    if confirmed:
        say("Остались ли у вас вопросы?")
        if no_more_questions(listen()): say(bye_confirmed); end
    else:
        say("Подскажите, вы придёте?")
```

# Часть 2. JavaScript

## Задача 1

```js
// ЗАДАЧА 1: формирование текста напоминания для робота.

const appointment = {
  patientName: "Анна",
  doctor: "Иванов Сергей Петрович",
  specialty: "терапевт",
  date: "2026-10-12",
  time: "15:30"
};

// "2026-10-12" -> "12.10.2026".
// Разбираем строку вручную, а не через new Date(), чтобы часовой пояс
// сервера не мог сдвинуть дату на день.
function formatDate(isoDate) {
  const [year, month, day] = isoDate.split("-");
  return `${day}.${month}.${year}`;
}

function buildReminderText(a) {
  return `${a.patientName}, вы записаны к врачу ${a.doctor}, ${a.specialty}, на ${formatDate(a.date)} в ${a.time}.`;
}

console.log(buildReminderText(appointment));
// Анна, вы записаны к врачу Иванов Сергей Петрович, терапевт, на 12.10.2026 в 15:30.

```

## Задача 2

```js
// ЗАДАЧА 2: преобразование ответа API в массив строк.

const response = {
  success: true,
  appointments: [
    { id: "A-101", doctor: "Иванов", time: "10:00" },
    { id: "A-102", doctor: "Петров", time: "14:30" }
  ]
};

function toDoctorTimeList(res) {
  // Если API вернул ошибку или список отсутствует, отдаём пустой массив,
  // чтобы сценарий робота не упал.
  if (!res || !res.success || !Array.isArray(res.appointments)) {

  }
  return res.appointments.map(a => `${a.doctor} — ${a.time}`);
}

console.log(toDoctorTimeList(response));

# Часть 3. Работа с LLM: промпт для извлечения данных о товаре

## Промпт (system)

```
Ты — модуль извлечения данных для голосового робота аптеки.
На вход ты получаешь расшифровку реплики клиента (распознанную речь, возможны ошибки распознавания и разговорные слова).
Твоя задача — извлечь информацию о товаре, который ищет клиент, и вернуть её в виде JSON.

Формат ответа — строго один JSON-объект с четырьмя полями:
{
  "product": string | null,
  "dosage": string | null,
  "form": string | null,
  "package": string | null
}

Правила для полей:
1. product — название препарата или товара так, как его назвал клиент, с заглавной буквы, включая уточнения, которые являются частью названия («детский», «форте», «экспресс»).
   Если клиент не назвал конкретный товар, а описал только проблему («что-нибудь от аллергии», «от головы»), product = null.
2. dosage — дозировка действующего вещества, только если клиент её произнёс. Приводи к сокращённой записи: «500 миллиграмм» → «500 мг», «сто миллиграмм на пять миллилитров» → «100 мг/5 мл», «два процента» → «2%».
3. form — лекарственная форма, только если клиент её назвал: «таблетки», «капсулы», «сироп», «суспензия», «мазь», «гель», «спрей», «капли», «раствор», «свечи» и т. п. Используй форму множественного числа, если так принято («таблетки», «капсулы», «свечи»).
4. package — фасовка или размер упаковки, только если клиент их назвал: количество единиц («20 таблеток»), объём («100 мл»), масса («30 г») или словесное описание размера («большой флакон»). Числа, произнесённые словами, записывай цифрами.

Главные ограничения:
- Не придумывай и не дополняй данные. Если значение не прозвучало в реплике — верни null. Не подставляй «типичную» дозировку, форму или упаковку, даже если знаешь, в каком виде обычно выпускается препарат.
- Не выводи форму из дозировки и дозировку из формы.
- Если клиент назвал несколько товаров, верни данные только о первом названном товаре.
- Если реплика не относится к поиску товара, верни все поля равными null.
- Не давай медицинских советов и не предлагай аналоги.

Ответ: только JSON-объект, без пояснений, без markdown-разметки (без ```), без текста до или после.

Примеры:

Реплика: «Мне нужен Нурофен детский, сироп»
Ответ: {"product": "Нурофен детский", "dosage": null, "form": "сироп", "package": null}

Реплика: «Есть у вас парацетамол 500 миллиграмм, упаковка на 20 таблеток?»
Ответ: {"product": "Парацетамол", "dosage": "500 мг", "form": "таблетки", "package": "20 таблеток"}

Реплика: «Мне нужен Нурофен детский, сироп, большой флакон»
Ответ: {"product": "Нурофен детский", "dosage": null, "form": "сироп", "package": "большой флакон"}

Реплика: «Мне что-нибудь от аллергии»
Ответ: {"product": null, "dosage": null, "form": null, "package": null}
```

## Сообщение пользователя (user)

```
Реплика клиента: «{{client_text}}»
```

`{{client_text}}` — переменная, в которую сценарий подставляет распознанную речь.

## Почему промпт устроен именно так

- **Схема и правила по каждому полю** — модель знает, что класть в какое поле и как нормализовать значения (например, «500 миллиграмм» → «500 мг»), чтобы поиск в аптечной системе работал по единому формату.
- **Отдельный блок «Не придумывай»** — главный риск в этой задаче: модель «знает», что Нурофен детский выпускается 100 мг/5 мл, и может подставить это без запроса клиента. Явный запрет плюс пример с null снижают этот риск.
- **Few-shot примеры** — включают пример из задания, пример со всеми полями и пример «от аллергии», где товар не назван.
- **Только JSON** — ответ сразу разбирается кодом (`JSON.parse`). Дополнительно в настройках модели стоит включить JSON mode / structured output, если платформа это позволяет, и в сценарии обернуть разбор в `try/catch`: при ошибке переспросить клиента.
- **Температура 0** — для извлечения данных нужна предсказуемость, а не креативность.

## Что делает сценарий после ответа LLM

- `product = null` → робот уточняет: «Подскажите, какой именно препарат вы ищете?» (для «от аллергии» — перевод на фармацевта, так как подбор лекарства — это консультация).
- Есть `product`, но нет `form`/`dosage`, а в системе несколько вариантов → робот перечисляет варианты и уточняет.
